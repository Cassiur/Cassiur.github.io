📚 源码级深度解析

1. 策略模式深度解析

1.1 策略模式是什么？

生活化比喻：

  • 就像你去餐厅点餐，可以选中餐、西餐、日料
  • 每种菜系都是一个策略，你可以随时切换
  • 但点餐的流程是一样的（看菜单 → 点菜 → 付款 → 上菜）

源码解析：ChatService 接口

策略模式的三个角色：

  1. 策略接口（ChatService）：定义所有策略的通用方法
  2. 具体策略（ChatGPTService、WenXinYiYanService）：实现策略接口
  3. 上下文（ChatServiceFactory）：维护一个策略实例的引用

1.2 策略模式的实现

生活化比喻：

  • 就像餐厅的菜单（策略接口），上面有各种菜系（具体策略）
  • 你点餐后，服务员（上下文）把你的订单发给对应的厨师（具体策略）

源码解析：ChatServiceFactory（上下文）

执行流程：

  1. 用户选择 AI 类型（ChatGPT、文心一言等）
  2. 调用 ChatServiceFactory.getChatService(aiSource)
  3. 返回对应的 ChatService 实现类
  4. 调用 chatService.chat(user, question)

优点：

  • ✅ 开闭原则：新增 AI 类型，只需要添加新的 ChatService 实现类，不用修改现有代码
  • ✅ 避免大量的 if-else：不用写 if (aiType == CHAT_GPT) { ... } else if (aiType == WEN_XIN_YI_YAN) { ... }

1.3 工厂模式深度解析

生活化比喻：

  • 就像工厂生产产品，你只需要告诉工厂”我要 ChatGPT”，工厂就会给你一个 ChatGPT 实例
  • 你不需要知道 ChatGPT 是怎么创建的，只需要知道怎么用

源码解析：ChatServiceFactory

标准工厂模式 vs 注册式工厂：

特性 标准工厂模式 注册式工厂（当前实现）
创建实例 工厂创建 Spring 创建
依赖注入 不支持 支持
性能 差（每次创建新实例） 好（复用实例）
复杂度 低 中

为什么用注册式工厂？

  • ✅ 支持依赖注入：所有的 ChatService 实现类都是 Spring Bean，可以注入其他 Bean
  • ✅ 性能好：复用实例，不每次创建新实例
  • ✅ 代码简洁：不需要写大量的 if-else

2. WebSocket 深度解析

2.1 WebSocket 是什么？

生活化比喻：

  • HTTP：就像你给朋友写信，每次都要重新写地址、贴邮票、寄出去
  • WebSocket：就像你给朋友打电话，建立连接后，可以随时互相说话

HTTP vs WebSocket：

特性 HTTP WebSocket
连接 短连接（每次请求都要建立连接） 长连接（建立一次，一直保持）
方向 单向（客户端请求，服务器响应） 双向（客户端和服务器都可以主动发送消息）
实时性 差（要轮询） 好（服务器可以主动推送）

2.2 STOMP over WebSocket

生活化比喻：

  • WebSocket：就像一条电话线，可以传输任何数据
  • STOMP：就像电话线里的语言（比如中文、英文），规定了数据的格式

STOMP 协议：

  • 订阅：SUBSCRIBE /user/chat/rsp
  • 发送：SEND /app/chat
  • 消息：MESSAGE /chat/rsp

源码解析：WsChatConfig

执行流程：

  1. 客户端创建 WebSocket 连接：new WebSocket("ws://localhost:8080/gpt/123/ChatGPT")
  2. 服务器端 registerStompEndpoints() 处理连接请求
  3. 客户端订阅消息：stompClient.subscribe("/user/chat/rsp", callback)
  4. 服务器端 WsAnswerHelper.response() 发送消息：simpMessagingTemplate.convertAndSendToUser(session, "/chat/rsp", response)

2.3 WebSocket 流式推送

生活化比喻：

  • 就像你看直播，主播说一句话，你马上就能听到
  • 而不是等主播说完所有话，再一次性发给你

源码解析：WsAnswerHelper

流式推送的原理：

  1. AI 生成回答是一个流式的过程（一个字一个字生成）
  2. 每生成一个字，就调用一次 response(session, vo)
  3. 客户端收到消息后，把字追加到页面上
  4. 用户就能看到打字机效果（一个字一个字出现）

为什么是”毫秒级响应”？

  • HTTP 轮询：客户端每隔 1 秒发一次请求，检查 AI 是否回答完成
  • WebSocket 推送：AI 生成一个字，就推送一次，延迟只有几毫秒

📚 面试八股文

策略模式

问题 1：什么是策略模式？有什么优点？

回答：

  • 策略模式：定义一系列策略，把它们封装起来，并且使它们可以互相替换
  • 优点：开闭原则、避免大量的 if-else

问题 2：策略模式和工厂模式有什么区别？

回答：

  • 策略模式：关注算法的替换
  • 工厂模式：关注对象的创建

WebSocket

问题 3：什么是 WebSocket？和 HTTP 有什么区别？

回答：

  • WebSocket：双向通信协议，客户端和服务器都可以主动发送消息
  • HTTP：单向通信协议，只能客户端请求，服务器响应

问题 4：什么是 STOMP？有什么作用？

回答：

  • STOMP：简单的消息协议，规定了消息的格式
  • 作用：让 WebSocket 可以传输结构化的消息（订阅、发送、消息）

📝 总结

本文讲了什么？

  1. 策略模式：ChatService 接口 + 多个实现类
  2. 工厂模式：ChatServiceFactory（注册式工厂）
  3. WebSocket：STOMP over WebSocket，流式推送

发现的问题

  1. WebSocket 线程池配置可能不足
  2. 没有错误处理
  3. 没有限流

修复方案

  1. 增大线程池：corePoolSize=50, maxPoolSize=200
  2. 添加错误处理：捕获异常，发送错误信息给用户
  3. 添加限流：限制用户发送消息的频率
