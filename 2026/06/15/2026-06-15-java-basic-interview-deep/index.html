⚠️ 常见陷阱与误区

陷阱 1：混淆 == 和 equals()

❌ 错误理解：

  • 以为 == 比较的是值，equals() 比较的也是值

✅ 正确认知：

  • ==：比较基本数据类型的值，比较引用类型的地址
  • equals()：默认比较地址，但可以被重写（如 String 重写 equals() 比较内容）

陷阱 2：String 是不可变的，但 StringBuilder 是可变的

❌ 错误理解：

  • 以为 String 是可变的，可以修改字符串内容

✅ 正确认知：

  • String 是不可变的：任何对 String 的修改都会创建新的 String 对象
  • StringBuilder 是可变的：可以在原对象上修改，性能更高

陷阱 3：hashCode() 和 equals() 必须同时重写

❌ 错误做法：

  • 只重写 equals()，不重写 hashCode()

✅ 正确做法：

  • equals() 相等，hashCode() 必须相等
  • hashCode() 相等，equals() 不一定相等
  • 如果只重写 equals() 不重写 hashCode()，会导致 HashMap、HashSet 等基于哈希的集合无法正常工作

💡 面试技巧

🎯 面试技巧：面试时遇到 Java 基础问题，不要只背概念，要结合实际项目经验回答。

回答思路

  1. 先说一句话总结：简洁明了地回答问题的核心
  2. 再深入解析：解释原理、底层实现、优缺点
  3. 最后面试加分回答：结合实际项目经验，举例说明

举例说明

问题：HashMap 和 Hashtable 的区别是什么？

一句话总结：HashMap 线程不安全、允许 null 键值；Hashtable 线程安全、不允许 null 键值。

深入解析：

  • HashMap 底层是数组 + 链表/红黑树，Hashtable 底层是数组 + 链表
  • HashMap 的 put、get 方法没有加锁，线程不安全；Hashtable 的 put、get 方法加了 synchronized 锁，线程安全
  • HashMap 允许 key 和 value 为 null；Hashtable 不允许 key 和 value 为 null

面试加分回答：

“在实际项目中，我通常使用 HashMap，因为性能更高。如果需要线程安全，我会使用 ConcurrentHashMap，而不是 Hashtable，因为 ConcurrentHashMap 的并发性能更高（分段锁/JDK 1.8 的 CAS + synchronized）”
