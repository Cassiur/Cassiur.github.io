AI 应用工程八股文：LLM、RAG、Agent、Function Calling、MCP 与 Skills 160 问

模型生成一份JSON、应用执行一个函数、Agent完成一个任务，是三个不同层次的问题。学习AI应用工程，需要把模型能力、协议与普通软件工程放到同一条链路里理解。

这里按八个专题整理160问。每题包含核心回答、原理或工程取舍，以及容易混淆的边界和追问。适合建立知识体系、查漏补缺和准备通用技术面试，不绑定任何公司、招聘批次或个人经历。

先分清这几个概念

概念 主要回答的问题 不能据此推导什么
LLM 如何根据上下文建模和生成内容 输出必然真实
RAG 如何找到并使用外部资料 带引用就一定正确
Function Calling 如何表达结构化工具调用及参数 模型已经执行动作
Structured Outputs 如何让输出符合支持的结构约束 业务数据与权限正确
MCP 应用怎样与上下文、工具服务交互 自动提供完整安全和事务
Agent 谁根据反馈决定后续行动 工具越多就越自主可靠
Skill 怎样打包任务方法与资源 文档能授予执行权限
Harness 如何管理执行、状态、预算和验证 使用某框架就万事俱备

一条完整的AI应用链路

推荐学习顺序

初次系统学习

先读LLM基础，理解Token、上下文和推理；再读Prompt与RAG，知道信息从哪里来；之后读Function Calling与MCP，分清模型提议、工具执行与协议；最后读Agent编排、评测和部署。

已有后端经验

可以先读Function Calling，再读MCP、Agent和安全。把已有的身份认证、事务、重试、消息、状态机与可观察性知识接到AI链路中，再补模型和检索基础。

快速查漏

  • 概念说不清：每篇Q1–3。
  • 工具调用不熟：Function Calling Q3–15及完整调用示例。
  • MCP容易混版本：MCP Q4–17及最小消息序列。
  • RAG只会讲流程：RAG Q5–18，重点分数融合、过滤、引用与评测。
  • 想做生产应用：安全篇Q6–20、部署篇Q7–19。
  • 想深入Skills：Agent与Skills篇Q10–16。

八个常见错误结论

  1. 严格JSON输出能保证事实正确。
  2. 模型提出了函数调用，就表示函数已经执行。
  3. MCP就是Function Calling，或者就是HTTP接口加一层名字。
  4. Skill就是一个后台Agent，也能直接授予权限。
  5. 向量相似分数可以解释成正确率。
  6. 多Agent相互同意就等于结果已验证。
  7. 请求超时代表业务没有发生，可以直接重试。
  8. 首字更快、Token更少，就一定使完整业务更便宜。

对应专题都解释了原因、适用条件和验证办法。学习时把“它是什么”进一步练成“什么时候用、哪里会失败、如何证明”。

范围与版本

这是一套应用工程知识库，涵盖必要的模型基础，不替代完整的深度学习数学、GPU内核、分布式训练与论文研究课程。没有采用固定价格、当前榜单或模型版本排名，避免把易变信息背成定律。

MCP专题固定使用2025-11-25规范；厂商API仅在明确指向其官方文档时讨论对应行为，教学JSON不假装是通用SDK请求体。资料核对日期为2026年11月1日。参考资料分列在每篇末尾。
